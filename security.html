Architecture & Trust

GoFully Security

Your screenshots are your data. Built with security and local isolation in mind.

GoFully is built to make capturing and working with webpage content simple without unnecessarily moving that content outside your browser sandbox.

1. Four Core Security Principles

Local by design

GoFully's core capture, annotation, privacy editing, OCR, and export workflows are designed to operate locally in your browser. Your screenshots should not need to travel to a remote server just to capture or edit them.

Minimal access (Least Privilege)

GoFully requests browser permissions based strictly on the functionality required to capture and process webpage content. We follow the principle of least privilege: permissions exist because a feature needs them, not because they might be useful later.

No advertising profiles

GoFully does not use captured webpage content to build advertising profiles. Your screenshots, captured text, and edited images are not intended to become a source of behavioral advertising data.

You stay in control

GoFully lets you decide what to capture, what to blur, what to pixelate, what to redact, what to copy, and what to export. Before sharing a screenshot, always review it for sensitive information.

2. Data Handling & Storage

GoFully does not maintain any external user database or cloud backend for captures.

  • In-Memory Processing: Raw pixel bitmaps are assembled in browser memory (`OffscreenCanvas`) and discarded when tabs or editors are closed.
  • Local OCR Execution: Text extraction is performed entirely on-device via WebAssembly (Tesseract.js). No OCR queries are transmitted to third-party APIs.
  • Client-Side Export: PNG, JPG, and PDF conversions occur directly inside your browser engine. Files are written directly to your local filesystem.

3. Permission Justifications

GoFully requests only the minimum permissions required under Chrome Manifest V3:

  • activeTab: Grants temporary access to the active webpage only when you click the extension icon or trigger a hotkey.
  • scripting: Injects content scripts to measure page dimensions, handle fixed headers during scrolling, and render the in-page result HUD.
  • offscreen: Creates an isolated background document for stitch operations and WebAssembly OCR processing without slowing down active tabs.
  • downloads: Allows the extension to save finished PNG and PDF files directly to your device's Downloads directory upon request.
  • storage: Stores your local configuration preferences (e.g., PDF orientation, zoom defaults) via Chrome's sync storage.
  • debugger: Enables direct CDP (`Page.captureScreenshot`) single-shot full-page capture for pixel-perfect fidelity.

4. Sensitive Information & Redaction

Screenshots can often contain sensitive credentials, personal messages, or confidential organizational data.

GoFully provides three distinct redaction tools built into the Annotation Studio:

  • Glass Smooth Blur: Gaussian-style progressive blur for subtle visual softening.
  • Mosaic Pixelate: High-density pixelation blocks to conceal identifiable text or photos.
  • Solid Blackout Redaction: Opaque solid rectangles for complete security redaction.
Security Recommendation
Redaction and blur tools should be treated as assistance. Always inspect the final exported image before publishing or sharing it publicly.

5. Browser Security Model

GoFully operates strictly within Google Chrome's Manifest V3 security boundaries.

  • Content Security Policy (CSP): All scripts, styles, and WebAssembly binaries are bundled inside the local package. No dynamic remote script evaluation (`eval()`) is permitted.
  • No External CDN Dependencies: Fonts, icons, and libraries are locally bundled within the verified CRX archive.
  • Single Purpose: GoFully adheres strictly to Chrome Web Store quality guidelines by maintaining a narrow, predictable focus: capturing, editing, and extracting webpage content.

6. Security Updates

We continuously audit our dependencies and release updates when improvements or browser policy adjustments are required. We strongly recommend keeping GoFully updated to the latest available version from the Chrome Web Store.

7. Report a Security Issue

If you discover a potential vulnerability or security concern in GoFully, please report it directly through our security intake channel:

  • Email: rahamanmuzeeb1108@gmail.com
  • GitHub Security Advisories: github.com/MUZEEBURRAHAMAN/gofully-extension/issues

When reporting, please include:

  1. A clear description of the vulnerability.
  2. Step-by-step instructions to reproduce the issue.
  3. Affected GoFully and Chrome versions.
  4. Relevant technical logs or screenshots.

Please allow us reasonable time to investigate and patch the issue before public disclosure.
