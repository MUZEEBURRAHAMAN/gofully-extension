Design System

The visual language behind GoFully — the full-page screenshot, OCR and annotation extension for Chrome — and its marketing site. Flat surfaces, square corners, registration-mark frames instead of shadows, and a single brand blue #1667F2 that only ever means "act here".

Bricolage Grotesque + Inter (site) Archivo (extension UI) Geist Mono (labels, code) border-radius: 0 — everywhere 4px base grid Phosphor icons · 3 tones Light + dark, equal citizens

The capture is the hero

Chrome stays flat and quiet so the user's screenshot — the thing they came for — carries every screen.

Square, not soft

A global border-radius: 0 reset. Circles are allowed only for things that are genuinely round: dots, badges, step numbers.

Frames, not shadows

On the site, depth comes from 1px hairlines and blueprint corner marks. Shadows are reserved for floating extension UI.

One blue, on purpose

Brand blue marks the primary action, the active tool and the selected state. Everything else is ink and grey.

03 · Iconography

Icons — three tones

Phosphor icons on a 256 grid, rendered in currentColor. Each glyph ships in three tones; the tone signals state, not decoration.

Icon set in use hover any cell

Every glyph mapped to its role in the popup, editor, result bar and site.

  • Outline (regular) — default for every toolbar, popup and nav icon.
  • Filled — the active tool, the selected capture mode, and "on" toggles. Filled means "this is the current state".
  • Duotone — marketing only: feature tags, use-case cards, empty states. Never inside the working UI.
  • Sizes: 16 inline · 18 toolbar · 20 capture-mode tiles · 26–34 feature cards. Always square, never stretched.
  • Migration note: the current build still ships hand-drawn stroke icons (1.6 toolbar / 1.8 action weight). This page is the target set.

08 · Elevation

Elevation

Two strategies. The extension floats above arbitrary web pages, so it uses blue-tinted shadows. The website sits on its own flat canvas, so it uses hairlines and blueprint corners — no shadows.

      Annotation & illustration

      The editor's annotation primitives share the brand blue so marked-up screenshots look like GoFully made them. Illustrations use the same ink + one-blue rule, framed by blueprint corners.

      Editor primitives

      Arrow (3px, round caps) · numbered step (24px circle, white ring) · ink callout · multiply highlighter at 22% · pixel/blur redaction.

      • Line: ink #1d1f20 at 3.4 on a 200 grid, round joins. No gradients, no drop shadows.
      • Accent: exactly one blue element per scene — the thing the user should notice (a check, a lens, the highlighted line).
      • Frame: every illustration sits inside blueprint corner marks, matching the site's cards.
      • Canvas: illustrations always render on white, even in dark mode — the ink line needs a light ground.

      15 · Reference

      CSS token map

      The source of truth for each surface. Use these variables — never raw hex in components.

      /* Website — app/globals.css (scoped under .gf-industry) */ --gf-color-bg: #f2f2f3; --gf-color-surface: #e9e9ea; --gf-color-text: #1d1f20; --gf-color-accent: #1667F2; --gf-color-accent-600: #1257D8; --gf-color-accent-700: #0E4AB8; --gf-color-accent-900: #1d2d3d; --gf-color-divider: color-mix(in srgb, #1d1f20 16%, transparent); --gf-font-heading: var(--font-heading); /* Bricolage Grotesque */ --gf-font-body: var(--font-sans); /* Inter */ /* Extension — src/popup/popup.html (light · dark) */ --blue: #1667F2 · #4C8DFF --blue-h: #1257D8 · #6BA0FF --blue-a: #0E4AB8 · #82B2FF --blue-bg: #EDF1FE · rgba(76,141,255,.14) --text: #101828 · #F0F2F5 --text-2: #344054 · #C5CAD3 --text-3: #667085 · #9AA1AF --border: #E3E8EF · #33383F --surface: #F7F8FA · #1B1D21 --card: #FFFFFF · #232529 --green: #027A48 · #2FBE79 --red: #B42318 --r-*: 0px /* all radii */ /* Editor — src/editor/editor.html */ --ink: 29,31,32 · 255,255,255 /* used as rgba(var(--ink), a) */ --bg: #d4d4d7 · #18181a /* canvas */ --bar: #f2f2f3 · #232326 /* toolbars */ --border: rgba(var(--ink), .12)

      Do

      • Keep every corner square; use a circle only for dots, badges and step numbers.
      • Use one primary blue button per view; everything else is secondary or ghost.
      • Frame site cards with BlueprintFrame instead of adding a shadow.
      • Pull colours from --gf-color-* (site) or Color.* (extension).
      • Write claims that are true in the shipped build: "on-device", "no upload".

      Don't

      • Add rounded-* classes — the global reset will silently override them anyway.
      • Use blue for decoration, section backgrounds or body text.
      • Mark a missing competitor feature in red; use a faint dash.
      • Put a shadow on a website card, or a blueprint frame inside the extension popup.
      • Loop animations at idle — only spinners and progress while work runs.
